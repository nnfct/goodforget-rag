GoodForget-RAG Architecture

A standalone view of the toy retrieval-control pipeline. The current implementation uses local TF-IDF vectors and deterministic evaluation, not an LLM.

1. User Query

Original request, which may include both useful intent and negative instructions.

2. Positive Intent

Oracle useful-information intent used to preserve adjacent allowed knowledge.

3. Forget Set

Separate forget-intent texts that describe evidence that should not be used.

4. Candidate Retrieval

TF-IDF vectors and cosine similarity produce candidate document scores.

5. Negative-Aware Reranking

Documents are rewarded for query and positive relevance, then penalized for closeness to the forget set.
S(d) = alpha * sim(q,d) + beta * sim(p,d) - gamma * max_i sim(f_i,d)

6. Filtered Context

Top-k evidence is selected after reranking and optional threshold removal.

7. Simulated Answer

Selected titles and snippets are concatenated. This is a deterministic proxy, not generated text.

8. Evaluation Metrics

Leakage, utility recall, safe context recall, over-filtering, removal precision, empty context, and answer proxy leakage.
