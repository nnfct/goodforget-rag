Hard Negative Pair Suite

Synthetic retrieval-time control benchmark. Not model unlearning, not guaranteed forgetting, and not proof of semantic forgetting. The purpose is to isolate whether the forget penalty changes near-duplicate rankings.

Compact Interpretation

  • What improved: this suite creates near-duplicate safe/forbidden pairs where Positive-only and Query Rewrite often retrieve forbidden evidence, making the forget penalty easier to isolate than in the broad validation benchmark.
  • Gamma effect: gamma > 0 substantially reduces leakage relative to gamma = 0 in most lexical representations and improves the safe-forbidden margin.
  • Against Positive-only / Query Rewrite: GoodForget gamma=0.5 improves leakage, but does not improve utility.
  • Against Metadata Filter: GoodForget does not beat oracle metadata filtering when labels are reliable.
  • Against Negative Vector: GoodForget is not clearly separated from the arithmetic negative-vector baseline across all representations.
  • Main limitations: synthetic templates, deterministic lexical representations, no LLM answer generation, and possible safe near-duplicate suppression.

Conservative Claim Box

The hard negative pair suite shows that gamma > 0 forget penalties can substantially reduce forbidden retrieval relative to gamma=0 and Positive-only retrieval in near-duplicate settings. However, GoodForget-RAG does not beat oracle metadata filtering, and the current suite does not consistently separate forget-intent penalty from the arithmetic negative-vector baseline across all representations.
